¿Qué es la Computación en la Nube?

La computación en la nube (cloud computing) es una tecnología que permite acceder remotamente, desde cualquier lugar del mundo y en cualquier momento, a software, almacenamiento de archivos y procesamiento de datos a través de internet, sin necesidad de un servidor local.

En lugar de comprar y mantener hardware propio, las organizaciones y personas acceden a recursos informáticos bajo demanda, pagando solo por lo que usan, como un servicio de electricidad o agua.

Definición NIST: modelo que permite el acceso de red ubicuo, conveniente y bajo demanda a un conjunto compartido de recursos informáticos configurables (redes, servidores, almacenamiento, aplicaciones y servicios) que se pueden aprovisionar y liberar rápidamente con mínimo esfuerzo de gestión.

Acceso remoto a recursos desde cualquier dispositivo.
Características esenciales del cloud
🔁 Autoservicio bajo demanda

El usuario puede aprovisionar recursos (servidores, almacenamiento) de forma unilateral, sin intervención humana del proveedor. En minutos se puede tener un servidor activo.

🌐 Acceso ubicuo por red

Los recursos están disponibles a través de la red desde cualquier dispositivo: PC, notebook, tablet, smartphone. Solo se necesita internet y credenciales.

📊 Medición del servicio

El uso de recursos se mide automáticamente. Se paga únicamente por lo consumido (modelo pay-as-you-go), sin costos fijos por hardware no utilizado.

Modelos de Servicio: IaaS, PaaS y SaaS

La computación en la nube se divide en tres modelos de servicio según el nivel de abstracción que ofrecen al usuario. Cada modelo delega distinta responsabilidad entre el proveedor y el cliente.

Modelo 1
IaaS
Infraestructura como Servicio

Las empresas contratan la infraestructura de hardware (servidores virtuales, almacenamiento, redes, procesamiento) a un tercero a cambio de una cuota. El cliente gestiona el sistema operativo y las aplicaciones; el proveedor gestiona el hardware físico.

Ejemplos: AWS EC2, Azure Virtual Machines, Google Compute Engine.

Modelo 2
PaaS
Plataforma como Servicio

El proveedor ofrece una plataforma completa para desarrollar, probar y desplegar aplicaciones: bases de datos, herramientas de desarrollo, middleware. El cliente solo gestiona sus aplicaciones y datos; el proveedor gestiona todo lo demás.

Ejemplos: Google App Engine, Azure App Service, Heroku, Cloud Foundry.

Modelo 3
SaaS
Software como Servicio

El proveedor aloja el software y lo pone a disposición del usuario a través de internet. El cliente accede desde cualquier lugar sin instalar nada localmente. El proveedor gestiona toda la infraestructura, plataforma y aplicación.

Ejemplos: Microsoft 365, Google Workspace, Salesforce, Zoom, Gmail.

Proveedores líderes en 2026
🟠 Amazon Web Services (AWS)

Líder del mercado con ~32% de cuota. Primer proveedor cloud masivo (2006). Ofrece más de 200 servicios: EC2 (VMs), S3 (almacenamiento), RDS (bases de datos), Lambda (serverless) y muchos más.

🔵 Microsoft Azure

Segundo proveedor con ~23% de cuota. Muy fuerte en empresas que ya usan productos Microsoft (Windows Server, Active Directory, Microsoft 365). Integración nativa con Windows 11 y servicios de IA (Azure OpenAI).

🟢 Google Cloud (GCP)

Tercero con ~12%. Muy fuerte en Big Data y Machine Learning (BigQuery, Vertex AI). Sus productos SaaS de uso masivo (Gmail, Drive, Docs) son el SaaS más usado del mundo por usuarios individuales.

Virtualización

La virtualización permite que una sola computadora física aloje múltiples computadoras virtuales independientes, llamadas Máquinas Virtuales (VM). Cada VM cree que tiene su propio hardware exclusivo, aunque en realidad comparte el hardware del equipo físico (host).

Arquitectura de virtualización de tipo 2: sobre el hardware físico corre un SO host, sobre el cual el software de virtualización (Hyper-V, VirtualBox, VMware) crea múltiples VMs independientes.
💻 Conceptos clave
  • Computadora host: la máquina física real
  • SO host: el sistema operativo de la máquina física
  • Máquina Virtual (VM): computadora virtual que corre sobre el host
  • SO invitado: el SO que corre dentro de la VM
  • Hipervisor: software que administra y aísla las VMs
  • Snapshot: imagen del estado actual de una VM, restaurable en cualquier momento
✅ ¿Para qué sirve la virtualización?
  • Probar nuevos sistemas operativos sin afectar el equipo real
  • Ejecutar software antiguo que no corre en SO modernos
  • Consolidar múltiples servidores en un solo hardware
  • Aislar aplicaciones y entornos de desarrollo
  • Recuperación ante desastres (backup de VMs completas)
  • Reducir costos de hardware y consumo eléctrico
Una sola computadora host puede ejecutar simultáneamente VMs con Windows, macOS, Linux y otros sistemas operativos, totalmente aisladas entre sí.
Implementación Tradicional vs. Virtualización
Implementación tradicional: cada servicio tiene su propio servidor físico dedicado con hardware completo, independientemente de si lo usa al 100% o no.
❌ Problemas del modelo tradicional
  • Recursos desperdiciados: un servidor de email puede usar solo el 10% de su CPU
  • Único punto de falla (SPOF) por servidor
  • Proliferación de servidores: más equipos = más espacio, energía y mantenimiento
  • Mayor tiempo de aprovisionamiento (semanas para comprar e instalar hardware nuevo)
Con virtualización, un solo servidor físico ejecuta múltiples VMs (DHCP, Active Directory, RADIUS, etc.), usando los recursos de forma más eficiente.
✅ Ventajas de la virtualización
  • Mejor uso de recursos (CPU, RAM, disco)
  • Menos espacio físico en el datacenter
  • Menor consumo eléctrico
  • Reducción de costos de hardware
  • Aprovisionamiento rápido (minutos)
  • Mayor tiempo de actividad y recuperación ante desastres

Hipervisores: Tipo 1 y Tipo 2

El hipervisor (también llamado VMM - Virtual Machine Monitor) es el software responsable de crear, ejecutar y gestionar las máquinas virtuales. Existen dos tipos según cómo se relacionan con el hardware.

Tipo 1 Nativo o Bare-Metal — Directamente sobre el Hardware

El hipervisor de tipo 1 se ejecuta directamente sobre el hardware físico, sin necesitar un sistema operativo host. Es como si el propio hipervisor fuera el sistema operativo del servidor.

Se usa principalmente en centros de datos, servidores empresariales y plataformas cloud. Ofrece mayor rendimiento, seguridad y eficiencia porque no hay un SO intermedio consumiendo recursos.

  • VMware vSphere/ESXi — estándar empresarial
  • Microsoft Hyper-V Server — integrado con ecosistema Microsoft
  • Xen / XCP-ng — open source, base de AWS
  • KVM — integrado en el kernel Linux
  • Oracle VM Server
Tipo 1: el hipervisor corre directamente sobre el hardware, sin SO intermedio.
Ejemplo real: VMware vSphere corre sobre el hardware y gestiona VMs con Windows Server, Linux y otros SO.
Tipo 2 Alojado o Hosted — Sobre un Sistema Operativo

El hipervisor de tipo 2 se ejecuta como una aplicación sobre un sistema operativo host existente (Windows, Linux o macOS). El SO host administra los recursos físicos y el hipervisor crea las VMs por encima.

Se usa principalmente para virtualización del lado del cliente: desarrolladores, técnicos y usuarios que quieren probar sistemas operativos o ejecutar múltiples entornos en su propia máquina.

  • VMware Workstation Pro
  • Oracle VirtualBox (gratuito y open source)
  • Windows Hyper-V (incluido en Windows 11 Pro)
  • Parallels Desktop (macOS)
Tipo 2: el hipervisor es una aplicación sobre el SO host, que gestiona las VMs por encima.
Ejemplo: Windows Hyper-V corriendo sobre Windows 10/11, con VMs de Windows 7, Linux y otros SO.

Es ideal para practicar en el laboratorio: se puede instalar Linux, Windows Server o cualquier otro SO dentro de una VM en tu propia notebook.

Contenedores, Kubernetes y Tendencias 2026

🐳 Contenedores vs Máquinas Virtuales

Mientras que las VMs virtualizan hardware completo (incluido el SO), los contenedores virtualizan solo a nivel de aplicación, compartiendo el kernel del SO host. Esto los hace más ligeros, rápidos de iniciar y eficientes en recursos.

📦 Docker — El estándar de contenedores

Docker permite empaquetar una aplicación con todas sus dependencias en un contenedor portable. El contenedor corre igual en cualquier entorno (desarrollo, testing, producción). Un contenedor inicia en milisegundos; una VM puede tardar minutos. En 2026 es la tecnología estándar de despliegue de software.

⚙️ Kubernetes (K8s) — Orquestación

Cuando se tienen cientos o miles de contenedores, se necesita un sistema que los administre automáticamente. Kubernetes (K8s) es el estándar open source de Google para orquestación de contenedores: escala automáticamente, distribuye carga, reinicia contenedores caídos y gestiona actualizaciones sin downtime.

Modelos de Nube: Pública, Privada e Híbrida
🌐 Nube Pública

Infraestructura compartida entre múltiples clientes, administrada por el proveedor (AWS, Azure, GCP). Costos bajos, escalabilidad ilimitada, pero menos control sobre la seguridad y privacidad de los datos.

🏢 Nube Privada

Infraestructura dedicada a una sola organización, ya sea en sus propias instalaciones o en datacenter propio. Mayor control y seguridad, pero mayores costos y menos elasticidad que la pública.

🔀 Nube Híbrida Tendencia

Combinación de nube pública y privada. Las cargas sensibles van a la privada; las que necesitan escala van a la pública. Es el modelo más adoptado por empresas en 2025–2026.

Otras Tendencias Clave 2026
⚡ Serverless Computing

El desarrollador solo escribe código (funciones) sin gestionar servidores. El proveedor ejecuta el código solo cuando se necesita y cobra por ejecución. Ejemplos: AWS Lambda, Azure Functions, Google Cloud Functions. Reduce costos y elimina la gestión de infraestructura.

🌍 Edge Computing

Procesamiento de datos cerca del origen (dispositivos IoT, cámaras, fábricas) en lugar de enviarlos a la nube central. Reduce latencia y dependencia del ancho de banda. Clave para vehículos autónomos, cirugía remota e industria 4.0.

💰 FinOps (Cloud Cost Management)

Disciplina emergente para optimizar los costos de la nube. El modelo pay-as-you-go puede generar facturas sorprendentes si no se gestiona bien. FinOps alinea equipos de tecnología y finanzas para maximizar el valor del gasto en cloud.

🤖 IA en la Nube

Los tres grandes proveedores ofrecen servicios de IA como API: AWS Bedrock, Azure OpenAI Service y Google Vertex AI. Las empresas integran modelos de lenguaje (GPT-4, Gemini, Claude) en sus aplicaciones sin entrenarlos desde cero, pagando por uso.

🪟
Windows 11 + Azure — Windows 365 Cloud PC: Microsoft ofrece un PC completo en la nube al que se accede desde cualquier dispositivo con un navegador. Windows 365 entrega un Windows 11 virtual personalizado, con aplicaciones, archivos y configuraciones, sin depender del hardware local. Es el ejemplo más concreto de SaaS de sistema operativo completo.
